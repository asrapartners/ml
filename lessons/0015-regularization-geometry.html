Regularization can prefer a shortcut

Same penalty idea as Lesson 0013's λβ², now compared two ways — L1 vs. L2 — with two candidate models that trade off fit against how their coefficients are shaped.

Two candidates, two norms

Two fitted logistic-regression candidates for the same task, four features each:

CandidateTraining log lossCoefficients β
C0.26(1.8, 0, 1.0, 0)
D0.30(0.7, 0.7, 0.7, 0.7)

‖β‖₁ = Σ|βj| is just "add up the sizes, ignore sign." ‖β‖₂² = Σβj² squares first, so a single large coefficient contributes disproportionately more than several small ones.

Candidate‖β‖₁‖β‖₂²
C1.8+1.0 = 2.81.8²+1.0² = 3.24+1.0 = 4.24
D4×0.7 = 2.84×0.7² = 1.96

Notice: the two candidates tie exactly on ‖β‖₁ (both 2.8) but not on ‖β‖₂² (4.24 vs 1.96). C is sparser — two of its four coefficients are exactly zero. D has the smaller squared-L2 penalty, because spreading the same total size across four small numbers costs much less once you square each of them.

The tie matters: it flips which candidate wins

Because the L1 penalty is identical for both (2.8 = 2.8), the L1-regularized objective is decided entirely by which had the better raw fit — C. The L2 penalty is not tied, and it punishes C's concentration into two larger coefficients heavily enough to flip the winner to D, despite D's worse raw fit. Same two candidates, same λ — different regularizer, different answer.

Round vs. cornered: why L1 zeroes things out and L2 doesn't

Picture the penalty as a boundary around the origin that the optimizer isn't allowed to cross while chasing lower loss. ‖β‖₂² ≤ c is a smooth circle (or sphere, in more dimensions) — the loss function's contours, sliding inward, tend to first touch that boundary somewhere round, rarely exactly on an axis, so L2 solutions usually end up with every coefficient shrunk a little, few landing at exactly zero. ‖β‖₁ ≤ c is a diamond with sharp corners sitting exactly on the axes — and it's disproportionately likely that the loss contour first touches the diamond at one of those corners, where one or more coordinates are exactly zero. That's the geometric reason L1 produces sparsity and L2 produces distributed shrinkage instead.

When a coefficient is zero for the wrong reason

Homework 1(d) makes this concrete: a camera-border feature became correlated with blocked walkways only because that camera happened to be used mostly after storms — a spurious pattern from how the data was collected, not a real cause of accessibility problems.

Proposed fixAssumption required to preserve the label
Modest brightness adjustmentWhether a walkway needs review doesn't depend on lighting — the ground truth (obstructed or not) is unaffected by how bright the photo looks.
Crop away every image borderNo genuinely useful signal about the walkway itself lives in the border region being cropped — only the confound does. If real obstruction cues sometimes appear near the edge of frame, cropping would also destroy real information.

Two checks worth running: a holdout check — evaluate separately on images from the storm-camera vs. other cameras, and see if performance (or the feature's importance) differs sharply between them, which would expose the shortcut; and an intervention on the suspected feature directly — e.g. swap or blank out the border pattern across otherwise-identical images and see whether the model's prediction changes, which would reveal it was leaning on the border rather than the obstruction itself.
