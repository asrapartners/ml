Lesson 0013 · Homework 1, Problem 2

Log loss and one gradient descent step

Lesson 0006 promised "want to walk one concrete gradient step with actual numbers? Just ask." This is that walk — with a different four points than Homework 1 uses, so the arithmetic itself stays yours to do.

The sigmoid: squashing a score into (0,1)

Logistic regression scores a point x by βx — same linear form as linear regression — then squashes that raw number through the sigmoid, σ(z) = 1/(1+e−z), so it always lands strictly between 0 and 1 and can be read as a probability. σ(0) = 0.5 always: a raw score of exactly zero means "no lean either way," regardless of what the data looks like.

Log loss: how wrong is the current guess?

For a point with true label y and predicted probability p, log loss is −[y·log p + (1−y)·log(1−p)]. Only one of the two terms is ever "active": if y = 1, it's −log p (penalizes low p); if y = 0, it's −log(1−p) (penalizes high p). Average that over all n points and you get L(β) — the same "how wrong, on average" role that mean squared error plays for numeric predictions, just built for probabilities instead.

Try it: one gradient step, live

Four points, separated cleanly by the sign of x: (−3, 0), (−1, 0), (1, 1), (3, 1). Start at β = 0, read off the loss, then hit the button to take one step with learning rate η = 1.

At β = 0, every point gets p = σ(0) = 0.5 — the curve is flat and uncommitted, and L(0) = ln 2 ≈ 0.693 for any dataset shaped like this, since −log(0.5) is the same number no matter what x is. That's worth noticing on its own: β = 0 always gives the same starting loss, regardless of the data — the interesting part only starts once you compute the gradient.

The gradient L′(β) = (1/n)Σ(pi − yi)xi is an average of "(how wrong) × (which direction x pointed)." At β = 0 here it comes out negative — because the negative-labeled points sit at negative x and the positive-labeled points sit at positive x, so their error-times-x products all point the same way. A negative gradient means "increasing β would reduce the loss," which is exactly why the update β(1) = β(0) − η·L′(β(0)) subtracts a negative number and pushes β up.

For Homework 1(a)–(b): the homework's four points are (−2,0), (−1,0), (1,1), (2,1) — different spacing than the demo above. Redo the same three computations by hand: pi at β(0)=0, L(β(0)), and L′(β(0)). The structure is identical; the numbers won't match this page.

After the step: lower loss, but not proof of anything yet

Take the step in the demo above and watch the curve steepen — probabilities move away from 0.5 toward the correct side for each point, and the average loss drops. Homework 1(c) points out something important here: once every point crosses the t = 0.50 threshold on the correct side, all four training points classify correctly. That fact does not mean training should stop, and it does not say anything about new data.

Why unbounded β is a problem, and what λβ² does about it

These four points are completely separated by the sign of x — every negative x is labeled 0, every positive x is labeled 1. That means increasing |β| without limit keeps squashing pi closer to the correct extreme (0 or 1) for every point, so log loss keeps falling — it never bottoms out at a finite β. Left alone, gradient descent on separated data drives β toward infinity.

Adding λβ² to the objective changes the shape of what's being minimized: past some point, any further increase in |β| costs more in penalty than it saves in loss, so the combined objective L(β) + λβ² has a genuine finite minimum instead of chasing β to infinity.

λ is a hyperparameter — a knob you set before training, not something gradient descent fits from the data (that's what β is). Hyperparameters like λ get chosen using a validation split — try a few values, see which does best on data the model wasn't fit on — and the test split is reserved untouched, so the final reported number isn't itself the result of tuning choices made against it.
