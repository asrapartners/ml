# Programmer background, notation is the barrier — not the concepts

The user is an experienced software programmer with no formal ML/stats background. They already have solid intuition for what ML *is* (a probabilistic system with weights tuned on data) — the friction is unfamiliarity with math notation conventions (e.g. the `ˆ` "hat" meaning "estimated from data" vs. the true/unknown quantity), not the underlying ideas.

**Implication for future lessons:** don't gloss over notation as "obvious." Define every symbol on first use, and prefer programming analogies (interfaces vs. implementations, type signatures, function composition) over stats-textbook framing. Conversely, don't over-explain concepts that map directly to things a programmer already knows (e.g. "a fixed procedure that takes data and returns a function" — that's just a higher-order function, say so explicitly).
